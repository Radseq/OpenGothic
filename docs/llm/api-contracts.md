# API Contracts

## Client Flags

Stable MMO flags:

- `-mmo-client-server host:port` - opt into server-bound mode and ASIO UDP.
- `-mmo-server-endpoint host:port` - endpoint alias/config path.
- `-mmo-action-session-key KEY` - client/server session key.
- `-mmo-action-jsonl PATH` - diagnostic evidence only.
- `-mmo-action-udp` - legacy diagnostic UDP path.

Rules:

- No server-bound behavior without explicit flags.
- Do not add per-domain restore flags for normal materialization.
- `-mmo-client-server` is the global server-bound materialization switch.

## Server Content Cache Flags

Stable C++ server flags:

- `--runtime-read-model PATH` / `--runtime-read-model-path PATH` - load
  `mmo.content_build_runtime_read_model.v1` during server startup.
- `--content-revision-key KEY` - active server content revision expected by the
  cache.
- `--world-instance-key KEY` - server world instance key bound to the cache.
- `--world-name NAME` - world name bound to the cache.
- `--startup-check-only` - validate startup/cache and exit before UDP loop.

Rules:

- No content cache is loaded unless `--runtime-read-model*` is provided.
- `content_revision_key` mismatch is fatal by default.
- Loading the cache does not mutate DB and does not execute scripts.

## UDP/Bootstrap

Server path:

```text
client_bootstrap_request
-> binary bootstrap ACK/NACK
-> optional chunked mmo_bootstrap_snapshot_v1 JSON
-> client writes runtime/mmo_server_bootstrap_snapshot.json
```

Rules:

- Ready ACK does not prove snapshot delivery.
- Missing snapshot after ready ACK is a server snapshot-build or transport bug.
- Rejected actions should provide NACK/diagnostic reason.

## Runtime Read-Model

Current content read-model schema:

- schema: `mmo.content_build_runtime_read_model.v1`
- export kind: `server_cache_read_model_json_v1`
- marker table: `mmo_content_build.content_build_runtime_exports`
- C++ probe target: `mmo_runtime_read_model_probe`

Required sections:

- `world_zen_entities`
- `waypoint_edges`
- `npc_templates`
- `item_templates`
- `routines`
- `perception_bindings`
- `dialog_infos`
- `dialog_outputs`

Current C++ runtime indexes:

- `worldZenEntityByKey`
- `waypointEdgeByRoute`
- `npcTemplateByInstance`
- `itemTemplateByInstance`
- `routinesByNpcInstance`
- `routinesBySymbol`
- `perceptionBindingsByKind`
- `perceptionBindingsByOwner`
- `dialogInfoBySymbol`
- `dialogOutputByName`

Rules:

- Do not rename JSON fields without updating exporter, probe and docs.
- `payload_sha256` is lowercase hex SHA-256 over the canonical exported payload.
- Marker SQL is generated by default; DB apply must be explicit.
- Missing `npc_instance` on routines and missing `owner_symbol` on perception
  bindings are currently probe warnings, not hard validation errors.

## World Instance Content Cache

Current C++ cache target:

- library: `mmo_world_instance_content_cache`
- probe: `mmo_world_instance_content_cache_probe`

Probe contract:

```text
mmo_world_instance_content_cache_probe \
  <runtime_read_model.json> \
  <content_revision_key> \
  <world_instance_key> \
  <world_name>
```

Rules:

- Cache is read-only and immutable after load.
- Cache owns the loaded `RuntimeReadModel`; returned records/ranges are tied to
  cache lifetime.
- `content_revision_key` mismatch is a hard error.
- `world_instance_key` and `world_name` are required.
- Cache loading does not mutate DB and does not execute scripts.
- `mmo_udp_server` adds `world_instance_content_cache` metadata to bootstrap
  snapshots when the cache is loaded and a snapshot is built.

## NPC Perception Policy

Current C++ policy target:

- library: `mmo_npc_perception_policy`
- probe: `mmo_npc_perception_policy_probe`

Probe contract:

```text
mmo_npc_perception_policy_probe \
  <runtime_read_model.json> \
  <content_revision_key> \
  <world_instance_key> \
  <world_name>
```

Rules:

- Policy consumes `WorldInstanceContentCache` and explicit actor sets.
- Policy does not execute Daedalus scripts.
- Policy does not mutate DB and does not broadcast packets.
- Output decisions are candidates for
  `mmo_ai_record_npc_perception_decision(...)`.
- Missing perception bindings produce no decision, not guessed behavior.

## AI Runtime Perception Recording

Current C++ recording targets:

- library: `mmo_npc_perception_runtime_source`
- library: `mmo_ai_runtime_persistence`
- probe: `mmo_npc_perception_record_probe`

Probe contract:

```text
mmo_npc_perception_record_probe \
  <mysql_url> \
  <runtime_read_model.json> \
  <content_revision_key> \
  <world_instance_key> \
  <world_name>
```

Rules:

- Default probe mode reads active actors from runtime DB.
- `--dry-run` must not mutate DB.
- `--synthetic` is a controlled dev/procedure validation path, not live AI.
- Recording must call `mmo_ai_record_npc_perception_decision(...)`.
- Recording requires `world_instance_uuid`, `npc_entity_key`, `target_key`,
  `perception_kind` and `idempotency_key`.
- `session_uuid` and `character_uuid` are carried when the player actor came
  from a live session.
- The probe does not broadcast movement/dialog/combat and does not execute
  Daedalus scripts.
- Automatic scheduling in `mmo_udp_server` is not enabled yet.

## MySQL Surfaces

Important schemas:

- runtime MMO DB - sessions, characters, current world state, event journal;
- `mmo_content_build` - parsed content build output;
- `mmo_ai_runtime` - NPC perception decisions and action queue.

Rules:

- `mmo_content_build` is not live gameplay state.
- `mmo_ai_runtime` is not parser output.
- Step SQL files are historical migrations/contracts.
- Procedure/table/view renames require compatibility or migration updates.

## Identity

Durable identity should use:

- character key;
- realm/world instance id/key;
- content revision key;
- world name;
- persistent id;
- symbol/script id;
- VOB id;
- item template symbol;
- DB UUID where available.

Never use display labels as durable identity.

## Serialized Field Compatibility

Compatibility-sensitive JSON/files:

- `runtime/mmo_server_bootstrap_snapshot.json`
- `runtime/mmo_server_bootstrap_snapshot_manifest.json`
- `runtime/content_build/parser_snapshot.json`
- `runtime/content_build/runtime_read_model.json`

Rules:

- Adding nullable/new fields is usually safe.
- Removing or renaming fields is breaking.
- Changing enum/string meanings is breaking.
- Keep legacy aliases until consumers are migrated.
